The problem

The spec should be the only source. It never is.

Every generated SDK — ours, the vendor's, the one you'd write — is only as true as the API description it was built from. And those descriptions routinely leave out what happens when a call fails. The types compile. The happy path works. Then production sends a status code the spec never mentioned, and your typed client hands you an untyped error.

Alchemy hits it

By the numbers What it takes to keep the SDKs Alchemy uses correct — computed from the patch files at build time.

You could fix this by hand-editing generated code — and lose it on the next regeneration. Or you could fix the description, once, and let every future build inherit the correction. That second thing is what Distilled is.

How it works

Generated from the spec. Proven by Alchemy.

Distilled turns each provider's API description into an SDK. Alchemy pulls Distilled in as a submodule and builds real infrastructure on it — resources, providers, tests against the live API. Every place the description turns out to be wrong comes back as a patch, and the next generation starts from the corrected spec.

What you get

Built on Effect, not wrapped in it.

Every operation returns an Effect. So the things an SDK usually bolts on — error handling, retries, pagination, configuration, tracing — are the Effect features you already use, with the provider's specifics filled in.

Typed errors

Every error the API can return is in the type signature. 

S3.getObject({ Bucket, Key }).pipe(
  Effect.catchTags({
    NoSuchKey:     () => Effect.succeed(null),
    AccessDenied:  (e) => Effect.fail(new Forbidden(e)),
  }),
  Effect.catchIf(isThrottlingError, () => backOff),  // by category
)

Match the exact error with catchTags, or a category — throttling, not-found, conflict — with catchIf. Nothing is unknown, and the compiler tells you when you've missed one.

Retries

Sensible retries by default. Change them in one place. 

// Default: exponential from 250ms, capped 5s, jittered, 8 tries,
// transient + throttling only, server Retry-After honoured.
program.pipe(AWS.Retry.throttling)   // retry throttles forever
program.pipe(AWS.Retry.none)         // or not at all
program.pipe(AWS.Retry.policy({      // or your own
  while:    isTransientError,
  schedule: Schedule.exponential("100 millis")
              .pipe(Schedule.recurs(3)),
}))

Transient and throttling errors are retried with backoff and jitter; a 404 never is. The API's own Retry-After is respected. Override the policy for one call or for the whole program — it's a Layer.

Pagination and streaming

List results and object bodies are Streams. Take ten items and only the first page is fetched. 

// Paginated: every page fetches itself, on demand.
const stale = Lambda.listFunctions.items({}).pipe(
  Stream.filter((fn) => fn.Runtime === "nodejs16.x"),
  Stream.take(50),
  Stream.runCollect,
)

// Bodies: a Stream<Uint8Array> in and out — no buffering the file.
const copy = S3.getObject({ Bucket: src, Key }).pipe(
  Effect.flatMap((o) =>
    S3.putObject({ Bucket: dst, Key, Body: o.Body! })),
)

Every paginated operation has .items() and .pages(). Large bodies — an S3 object, an upload — stream in and out without being held in memory. Cancel the Effect and the requests stop.

Configuration

Credentials, region and the HTTP client are provided once, not passed to every call. 

const AwsLive = Layer.mergeAll(
  FetchHttpClient.layer,
  Region.fromEnv(),
  Credentials.fromChain(),   // env → ~/.aws → SSO → IMDS
)

// In tests: same program, fake wire.
program.pipe(Effect.provide(MockHttpClient))

Your code calls S3.getObject; where the credentials come from is decided at the edge of the program. In tests, swap the HTTP client for a fake and nothing else changes — that is how the benchmarks on this site run without a network.

Tracing

Every request is already a span. Add an exporter and you have traces. 

// Effect's HttpClient opens a span per request, tagged with
// http.request.method, server.address, http.response.status_code.
program.pipe(
  Effect.withSpan("provision-bucket"),
  Effect.provide(OtlpTracer.layer({
    url: "http://collector:4318/v1/traces",
  })),
)

They are ordinary Effect spans, so they nest inside yours and go wherever your OpenTelemetry exporter sends them — Axiom, Datadog, Honeycomb, a local collector. Next: a named span per operation (S3.GetObject), not just per request.
