The problem

The spec is the only source. The spec is incomplete.

Every generated SDK — ours, the vendor's, the one you'd write — is only as true as the API description it was built from. And those descriptions routinely leave out what happens when a call fails. The types compile. The happy path works. Then production sends a status code the spec never mentioned, and your typed client hands you an untyped error.

Alchemy hits it
  • 20 of 112 S3 operations in AWS's own model declare any error at all. DeleteBucket declares none — not even NoSuchBucket or BucketNotEmpty.
  • 49 of 98 Fly Machines operations list a single 4xx response. Half the API is documented as if it cannot fail.
  • required PlanetScale marks storage and provider as required on cluster SKUs while sending them as null. A strict decoder rejects a valid response.
  • spec fixes carried across providers today, every one found by running real infrastructure through the SDK. See the tally →

You could fix this by hand-editing generated code — and lose it on the next regeneration. Or you could fix the description, once, and let every future build inherit the correction. That second thing is what Distilled is.

How it works

Generated from the spec. Proven by Alchemy.

A spec is a claim about an API, and claims are wrong in the details. Distilled generates the SDK from the provider's own description, then Alchemy builds real infrastructure resources on top of it — creating, updating and destroying things against the live API. Every mismatch that surfaces becomes a patch to the spec, not a hand-edit to the code, and the next regeneration carries it forward.

What you get

Not a wrapper. Effect all the way down.

Every operation is an Effect, so failure, retry, streaming, configuration and tracing are not SDK features you learn — they are the same primitives the rest of your program already uses.

Errors you can match on

Every failure the spec documents is a typed case — and every case carries a category. 

S3.getObject({ Bucket, Key }).pipe(
  Effect.catchTags({
    NoSuchKey:     () => Effect.succeed(null),
    AccessDenied:  (e) => Effect.fail(new Forbidden(e)),
  }),
  Effect.catchIf(isThrottlingError, () => backOff),  // by category
)

catchTags is exhaustive; nothing arrives as unknown. Categories — ThrottlingError, NotFoundError, ConflictError… — are attached to every error class, so you can handle a kind of failure without naming each provider-specific tag.

Retry is a Layer, not a loop

One policy for the whole SDK. Server hints honoured. Throttles retried, 404s never. 

// Default: exponential from 250ms, capped 5s, jittered, 8 tries,
// transient + throttling only, server Retry-After honoured.
program.pipe(AWS.Retry.throttling)   // retry throttles forever
program.pipe(AWS.Retry.none)         // or not at all
program.pipe(AWS.Retry.policy({      // or your own
  while:    isTransientError,
  schedule: Schedule.exponential("100 millis")
              .pipe(Schedule.recurs(3)),
}))

Every generated operation runs under the SDK's Retry service. Provide it once and every call below it inherits the policy; swap it per test, per request, or drop to a plain Effect Schedule when you need something exotic.

Streams, not arrays

Pages, items and bytes are all lazy. Pull what you need; the rest is never fetched. 

// Paginated: every page fetches itself, on demand.
const stale = Lambda.listFunctions.items({}).pipe(
  Stream.filter((fn) => fn.Runtime === "nodejs16.x"),
  Stream.take(50),
  Stream.runCollect,
)

// Bodies: a Stream<Uint8Array> in and out — no buffering the file.
const copy = S3.getObject({ Bucket: src, Key }).pipe(
  Effect.flatMap((o) =>
    S3.putObject({ Bucket: dst, Key, Body: o.Body! })),
)

.items() and .pages() on every paginated operation. Streaming request and response bodies for S3 and friends, so a multi-gigabyte object moves without touching memory. Back-pressure and cancellation come from Effect for free.

Configuration as Layers

Credentials, region, endpoint, HTTP client: services you provide, never arguments you thread. 

const AwsLive = Layer.mergeAll(
  FetchHttpClient.layer,
  Region.fromEnv(),
  Credentials.fromChain(),   // env → ~/.aws → SSO → IMDS
)

// In tests: same program, fake wire.
program.pipe(Effect.provide(MockHttpClient))

The program never mentions where credentials come from. Swap the HTTP client for a recorded one and the whole SDK runs offline; the benchmarks on this site are built exactly that way.

Traces out of the box

Every request is a span. Point an exporter at it and you have a waterfall. 

// Effect's HttpClient opens a span per request, tagged with
// http.request.method, server.address, http.response.status_code.
program.pipe(
  Effect.withSpan("provision-bucket"),
  Effect.provide(OtlpTracer.layer({
    url: "http://collector:4318/v1/traces",
  })),
)

No SDK-specific tracing API to learn: the spans are Effect spans, so they nest under yours and ship to Axiom, Datadog, Honeycomb or any OTLP endpoint through the exporter layer you already use. Per-operation spans with service and operation names are next.
